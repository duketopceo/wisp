# cua-driver recording / replay / verify (R4, 0.33.1, live-tested)

**Recording format.** `start_recording{output_dir, record_video?, include_accessibility_tree?, session?, state_timeout_ms?}` writes `turn-NNNNN/` per dispatched action call: `action.json` (tool, args, `action_truth` {effect delivered/refused/unverifiable, route, transport, refusal}, monotonic ms + epoch ts), `before.png`/`after.png`/`screenshot.png` (full-res 3456x2160), `click.png` (before.png + red marker — verified), `before_state.json`/`after_state.json` (AT-SPI walks, bounded, `truncated` flags), `evidence.json` (`cua-turn-evidence/v1` per-phase status; `privacy_suppressed` shots on foreign sessions). Plus `session.json`, `cursor.jsonl`. Verified live: read-only calls NOT recorded; every dispatched tool is (move_cursor, set_agent_cursor_*, browser_prepare — doc's action list is incomplete). Scope: `cua-driver recording start <dir>` = **daemon-wide** (captured r2/r3 agents' turns — noisy); `call start_recording{session:"x"}` = session-filtered, **survives across one-shot `call` connections** (fits wisp's `cua-driver call` transport). `record_video:true` works here via spawned `wf-recorder --no-damage -c libx264` (NOT ffmpeg — wf-recorder must be on PATH; produced h264 3456x2160@120fps mp4, moov finalized on stop). `recording render <dir> out.mp4` re-encodes video with zoom-ins at action points (~1.3x realtime). ffmpeg already at /usr/bin/ffmpeg (n9.0.2) — `install_ffmpeg` unneeded.

**Replay.** `replay_trajectory{dir, delay_ms=500, stop_on_error=true, session?}` — re-invokes each turn's `action.json` tool+args verbatim via the normal dispatch path, in lexical order (verified with synthetic dir; reports per-turn ok+summary). Blind replay: element_tokens die across sessions, pixel/keyboard calls replay clean; refuses nothing, records itself if recording is on (designed trajectory-diff regression workflow). NOT deterministic verification — it's re-execution.

**verify_state.** `{pid, window_id, expect[1-8], timeout_ms≤10s, stable_samples≤5, include_screenshot?}` — ANDed predicates: `window{exists, bounds{x,y,w,h,tolerance_px}}`, `element{selector{role,label_contains}, exists, enabled, selected, value_equals}`. Returns per-predicate satisfied/unsatisfied/unknown + `observed_json` evidence (verified: bounds+exists work; element went `unknown`/`untrusted_source` on thin AT-SPI — unknown never implies success).

**zoom** `{window_id,x1..y2}` → cropped JPEG ≤500px wide +20% pad (verified 407x203); registers `from_zoom` coord space for click/type_text. **parse_visual_regions** → `not_installed`: needs optional `cua-perception` extension (absent). **invoke_menu** `{pid,window_id,path[1-16]}` — AT-SPI menu path invocation, fail-closed (described, untested).

**VERDICT: yes, wire it — but only for cua-dispatched actions.** Recording only sees actions through the cua daemon: wisp's `cua` pointer backend (`platform.pointer_cmds` → `cua-driver call click scope:desktop`, verified working via `global_input`/`linux_wayland_virtual_pointer`) would be captured; clicklab's browseros-neo MCP DOM clicks would NOT. Plan: (1) `run.py` — wrap desktop-surface runs with `call start_recording{session:"clicklab-<run>", output_dir:<run-dir>}` at start / `stop_recording` at end, then reference turn dirs from clicklab.jsonl rows; keep video off unless demos wanted (multi-MB/turn PNGs + /tmp pressure). (2) `train.py` — `update_bank` needs no change (it folds judgments); optionally stash `turn_dir` in the rec for future media export. (3) Replay path — `replay_trajectory` is a free regression harness: record once, replay against a new build, diff trajectories + `verify_state` post-conditions (window bounds/exists reliable; element predicates flaky under thin AT-SPI). Caveats: per-window `background` delivery is refused on this box (`client_not_qualified` — libei path down); desktop-scope input works; AT-SPI trees are near-empty for foot/chromium-without-a11y so before/after state is often `no_target_pid`/partial.
